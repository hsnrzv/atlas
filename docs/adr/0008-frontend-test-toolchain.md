# ADR-0008: Frontend test toolchain — Vitest via the Angular CLI, Playwright with axe-core

- Status: Accepted
- Date: 2026-11-12
- Deciders: @hsnrzv (owner)

## Context

`project-instruction.md` §9.1 asks for the Angular-supported unit test runner (the current CLI default if mature),
Testing Library where useful, and Playwright for end-to-end, cross-browser and mobile viewport checks. §17.1 lists unit,
component, accessibility, flow and visual checks. `design-instructions.md` §11 and §16 require automated accessibility
checks, while noting they do not replace manual testing. Angular 22 projects generated by the CLI use the
`@angular/build:unit-test` builder with Vitest by default. Karma is deprecated.

Verified on 2026-11-12: Vitest 5.1.0, jsdom 30.1.3, `@playwright/test` 1.65.0, `@axe-core/playwright` 4.14.0.

## Decision

- **Unit and component tests:** `ng test` (`@angular/build:unit-test`, Vitest runner, jsdom). Specs sit next to the code
  (`*.spec.ts`). CI runs `ng test --watch=false`. Router-level tests use `RouterTestingHarness`.
- **Angular Testing Library is not added yet.** It will be introduced with the first interactive component (Phase 2) if
  it simplifies tests, recorded in the dependency matrix.
- **End-to-end:** Playwright with projects `desktop-chromium` and `mobile-chromium` (Pixel 7). It starts `ng serve`
  locally and reuses an existing server outside CI. Specs live in `e2e/`.
- **Automated accessibility:** `@axe-core/playwright` with WCAG 2.0/2.1/2.2 A and AA tags, run in light and dark
  themes on every page that has e2e coverage. Violations fail the build.
- **Design-system checks** (ADR-0007) run in the same CI job as the unit tests.
- Firefox and WebKit projects are added when the app shell lands (Phase 2). Capacitor device testing is Phase 10.
  Visual regression snapshots are deferred until layouts stabilise (Phase 2/3).

## Consequences

- Fast tests, no browser needed for unit tests, aligned with Angular's default and upgrade path.
- jsdom does not lay out pages. Layout, responsive and focus behaviour are therefore tested in Playwright, not in unit
  tests.
- axe catches a subset of WCAG issues. Keyboard and screen-reader checks stay in the PR checklist.
- CI needs the Playwright browser download (`npx playwright install --with-deps chromium`), roughly 1 minute.

## Alternatives considered

- **Karma + Jasmine:** the long-time Angular default, but deprecated and slower.
- **Jest (via a community builder):** mature, but not the Angular CLI default and needs extra configuration.
- **Cypress:** good developer experience, but weaker multi-browser and mobile emulation support than Playwright, which
  the specification names.
